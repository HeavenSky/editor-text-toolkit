# 把终端选中文本作为路径打开

[English](../../docs/open-terminal-selection.md) · **简体中文**

本页说明怎样在 VS Code 集成终端里选中一段路径，并按选中的原文打开对应文件，VS Code 自带的链接检测把路径切错时也能用；相对路径按该终端的当前目录解析。shell 集成（VS Code 默认开启）会让当前目录跟着每次 `cd` 变化；没有它也能用，只是目录没那么准。

## 打开选中的路径

先用鼠标选中路径，再任选一个入口；三个入口打开选中文本的方式完全相同。

| 入口         | 操作                                                                               |
| ------------ | ---------------------------------------------------------------------------------- |
| 快捷键       | macOS 上在终端获得焦点时按 Cmd+U；Windows 和 Linux 上要先[绑定快捷键](#绑定快捷键) |
| 终端右键菜单 | 在选区上右键，选择 `将终端选中文本作为路径打开`，它位于复制和粘贴下方              |
| 命令面板     | 执行 `文本工具箱: 将终端选中文本作为路径打开`                                      |

以下面这段编译输出为例，选中 `src/app.ts:12:5` 后会打开 `src/app.ts`，光标落在第 12 行第 5 列；即使 VS Code 自带的链接检测没把它认成完整路径，也能打开：

```text
$ npm run build
src/app.ts:12:5 - error TS2322: Type 'string' is not assignable to type 'number'.
```

Cmd+U 只在终端获得焦点时生效，在编辑器里仍是原来的作用。没有选中文本时它也会执行，因此能提供 Claude Code 这类全屏程序复制下来的路径，见[在 Claude Code 等全屏程序里选中](#在-claude-code-等全屏程序里选中)。Cmd+Y 打开的则是剪贴板里的路径，而不是选区。按住 Cmd 点击选区默认关闭，见[开启选区链接](#开启选区链接)。

打开终端后，命令面板里才会出现这条命令，它作用于当前活动的终端；右键菜单项只在有选中文本时出现，作用于你右键点击的那个终端。

## 能识别的路径写法

选中的文本整体当作一条路径，包括其中的空格；不会按空格或其他分隔符切开。先去掉外围的干扰：首尾空白、成对的引号、括号和反引号，以及末尾的 `,` `.` `:` 这类标点。

| 选中的文本                                                 | 打开的结果                                              |
| ---------------------------------------------------------- | ------------------------------------------------------- |
| `src/my file.ts`                                           | 终端当前目录下的 `src/my file.ts`                       |
| `"src/app.ts",` 或 `(src/app.ts)`                          | `src/app.ts`                                            |
| `src/app.ts:12`、`src/app.ts:12:5`、`src/app.ts:12-20`     | 第 12 行，写了列时到第 5 列；范围写法定位到起始位置     |
| `src/app.ts(12,5)`                                         | 第 12 行第 5 列                                         |
| `src/app.ts#L12`、`src/app.ts#L12C5`、`src/app.ts#L12-L20` | 第 12 行，写了列时到第 5 列                             |
| `File "app/main.py", line 42, in <module>`                 | `app/main.py` 的第 42 行                                |
| `~/notes/todo.md`                                          | home 目录下的 `notes/todo.md`                           |
| `file:///home/you/app.ts#L12`                              | `/home/you/app.ts` 的第 12 行；百分号编码的字符会被解码 |
| `git diff` 输出里的 `a/src/app.ts` 或 `b/src/app.ts`       | `a/src/app.ts` 存在时打开它，否则打开 `src/app.ts`      |
| macOS 与 Linux 上的 `my\ file.txt`                         | `my\ file.txt` 存在时打开它，否则打开 `my file.txt`     |
| Windows 上的 `C:\work\app.ts:3`                            | `C:\work\app.ts` 的第 3 行；盘符不会被当成行号          |

一段文本有多种读法时，取第一个在磁盘上存在的。`build.log:3` 打开 `build.log` 的第 3 行；只有 `build.log` 不存在时，才会打开一个名字就叫 `build.log:3` 的文件。行号为 0 视为没写行号；行号或列号超出范围时停在最后一行或行尾。图片和其他二进制文件用 VS Code 为它们选定的编辑器打开，行号被忽略。

`https://…` 这类网页链接留给 VS Code 处理。不展开 `$HOME`、`%USERPROFILE%` 这类环境变量，也不展开 `~user/` 写法。

选区跨多行时，每一行是一个候选，最多取前 20 行，多出的行被忽略时会有提示；只是在屏幕上折行显示的长行，终端会自己拼回一行。在某一行上点击选区链接，只打开这一行。

## 相对路径从哪个目录算起

相对路径从终端的当前目录算起。按下面的顺序逐个尝试，用第一个实际存在的目录：

1. 前台正在运行的程序（例如 Claude Code、vim）的当前目录，macOS 和 Linux 上从操作系统读取。只在有这样的程序运行时使用；像 `cd docs && claude` 这样写成一行时，shell 集成报的还是这行执行前的目录，这一级取到的才是对的。
2. shell 集成上报的目录，跟着每次 `cd` 变化。
3. shell 进程的当前目录（macOS 和 Linux 上从操作系统读取），同样跟着 `cd` 变化；Windows 上和终端已退出时跳过这一级。
4. 终端启动时的目录，不跟着 `cd` 变化。
5. 第一个工作区文件夹。
6. 都没有。这时只能打开绝对路径、`~` 路径和 `file://` 路径。

**感知不到 tmux、screen 和 ssh 里面的目录。** 这些程序报的是它们自己启动时的目录，而不是在它们里面运行的 shell 的目录。上报的目录在本机不存在时会被跳过。

扩展能取到 shell 集成上报的目录时，选区链接的悬停提示会显示 `将选中文本作为路径打开(相对于 …)`。在 Remote-SSH、WSL 或 Dev Container 窗口里，目录、`~` 和绝对路径指的都是远端机器上的位置。

## 打开目录

选中的是目录时，不打开编辑器，而是显示这个目录；写了行号也会被忽略：

| 目录所在位置                               | 结果                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| 在某个工作区文件夹内                       | 在资源管理器里定位并选中                                                 |
| 在工作区之外，且是本地窗口或 WSL 窗口      | 在访达、文件资源管理器或 Linux 的文件管理器里显示                        |
| 在工作区之外，且是 SSH、容器等其他远程窗口 | 提示 `目录不在当前工作区: …`，提供 `在新窗口打开` 和 `复制路径` 两个按钮 |

## 从多个路径中选一个

选区里有两行及以上的路径在磁盘上存在时，弹出一个列表，提示语为 `选中文本解析出多个路径, 选择要打开的一个`，列出所有行，存在的排在前面。只有一行的路径存在时，直接打开它，其余行忽略。

每一项标着 `文件`、`目录`、`不存在` 或 `无法访问`，并显示 `选区第 … 行 · …` 和完整路径，可以按路径过滤。选中标为 `不存在` 的一项后，按下一节的方式修正；按 `Esc` 取消。

## 修正不存在的路径

选区里的路径都不存在时，会弹出标题为 `将终端选中文本作为路径打开` 的输入框，预填你选中的那一行原文（选了多行时取第一行），引号和行号都保留：

1. 看输入框下方的提示。它写明相对路径从哪个目录算起以及这个目录的来源，例如 `相对路径基于: … (Shell 集成)`。
2. 修改文本。路径不存在时显示 `不存在: …`，不能回车；路径存在后提示变为 `将打开文件: …` 或 `将打开目录: …`。
3. 按回车。文件打开并定位到你写的行；按 `Esc` 取消，不做任何改动。

点回终端时输入框不会关闭，方便对照原始输出。也可以直接输入绝对路径、`~` 路径或 `file://` URI。路径存在但读不了（没有权限，或文件系统 1.5 秒内没有响应）时，不弹输入框，而是提示 `无法访问 …: …`，见[故障排查](troubleshooting.md)。

## 在 Claude Code 等全屏程序里选中

Claude Code 全屏模式这类接管鼠标的程序会自己画拖选高亮，终端本身并没有选区：选区链接和右键菜单项都不出现，执行命令会提示没有选中文本。用下面任一办法：

1. 按住 Option 拖动（Windows 和 Linux 上按住 Shift），得到真正的终端选区，再用任一入口打开。macOS 上需要 `"terminal.integrated.macOptionClickForcesSelection": true`，命令弹出的提示里有 `开启 Option+拖动选择` 按钮，点一下即可开启。
2. 照常在程序里选中。Claude Code 松开鼠标时会把选中文本复制到剪贴板；这时按 Cmd+Y，或执行 `文本工具箱: 将剪贴板内容按终端目录作为路径打开`，就能打开这个路径。相对路径按当前活动终端的当前目录解析，对 Claude Code 来说就是它启动时的目录。没有选中文本时按 Cmd+U，剪贴板里是存在的路径的话，提示里也会出现 `打开剪贴板中的路径` 按钮。

剪贴板文本的处理方式和选区相同：去掉周围的杂项，识别行号，多行时列出供选择，路径不存在时弹出输入框。相对路径要以某个终端的目录为起点，所以没有打开终端时，命令会提示 `请先聚焦到终端: 剪贴板中的相对路径按终端当前目录解析.`

## 绑定快捷键

macOS 上终端获得焦点时，按 Cmd+U 打开选区，按 Cmd+Y 打开剪贴板；Windows 和 Linux 上不预设快捷键。想换成别的键，把绑定写进 `keybindings.json`（执行 `首选项: 打开键盘快捷方式(JSON)`）：

```jsonc
// keybindings.json
[
	// macOS：关掉默认的 Cmd+U，改用 Ctrl+Cmd+U
	{ "key": "cmd+u", "command": "-textToolkit.terminal.openSelection" },
	{
		"key": "ctrl+cmd+u",
		"command": "textToolkit.terminal.openSelection",
		"when": "terminalFocus",
	},
	// Windows / Linux
	{
		"key": "ctrl+alt+o",
		"command": "textToolkit.terminal.openSelection",
		"when": "terminalFocus",
	},
	{
		"key": "ctrl+alt+shift+o",
		"command": "textToolkit.terminal.openClipboardPath",
		"when": "terminalFocus",
	},
]
```

`when` 里不要加 `terminalTextSelected`：Claude Code 这类全屏程序里终端没有选区，加了之后按键就不起作用。

macOS 上带 `cmd` 的快捷键在终端里直接生效。其他快捷键（Windows 和 Linux 上就是全部快捷键）会被终端交给 shell，所以还要在 `settings.json` 里加上这两条命令；不加的话按键被 shell 收走，什么也不会打开：

```json
{
	"terminal.integrated.commandsToSkipShell": [
		"textToolkit.terminal.openSelection",
		"textToolkit.terminal.openClipboardPath"
	]
}
```

## 开启选区链接

开启后，按住链接修饰键点击选中的文本就能打开，不用按快捷键。它默认关闭，因为选中之后要把鼠标移到别的行再移回来，链接才会出现，见[已知限制](#已知限制)。开启方法：

```json
{ "textToolkit.advanced": { "terminalOpen.selectionLink": true } }
```

修改立即生效。链接修饰键在 macOS 上是 Cmd，在 Windows 和 Linux 上是 Ctrl；`editor.multiCursorModifier` 为 `ctrlCmd` 时改为 Alt。链接只覆盖选中的文本，点击别处的行为不变；点击选中的文本时，选区链接优先于 VS Code 自带的链接。

## 已知限制

- 开启选区链接后，选中之后要等鼠标移到别的行再移回来，链接才会出现。VS Code 只在鼠标换到另一行时才向扩展索取这一行的链接，此前（还没选中时）取到的结果会一直沿用；移出终端再回到同一行，或在这一行里左右移动，都不算。右键菜单项和快捷键没有这个延迟。
- 一行超过 2000 个字符时，VS Code 不向扩展索取链接，选区链接不会出现；改用右键菜单项或快捷键。
- 选区从某个单词中间开始或结束时（例如从 `copyPath` 里只选了 `opyPath`），不会出现链接。
- 有选中文本期间，屏幕上其他位置的相同文本也会变成链接，打开的是同一个路径。
- Claude Code 在它自己的目录里执行命令：它的 Bash 工具执行过 `cd sub` 之后，后续命令输出里的相对路径是相对 `sub` 的，而扩展看到的仍是 Claude Code 启动时的目录。这样的路径会找不到，或打开启动目录下的同名文件；请选中绝对路径，或在输入框里改正路径。
- 长行恰好在空格处折行显示时，终端会丢掉这个空格，路径因此找不到；在输入框里把空格补回去即可。
- 读取选区依赖一个尚未定稿的 VS Code API。当前 VS Code 版本不提供它时，选区链接不会出现，其他入口会提示没有选中文本；这时先复制路径，再执行 `将剪贴板内容按终端目录作为路径打开`。
