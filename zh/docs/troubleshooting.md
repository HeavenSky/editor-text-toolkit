# 故障排查

[English](../../docs/troubleshooting.md) · **简体中文**

按看到的提示或现象查找，每条给出原因和解决办法。提示文字引自中文界面。

## 当前文档尚未保存为文件.

- **原因：** 在未命名文档，或输出面板、虚拟文档这类没有对应文件的文档上执行了 `复制路径与行号`。
- **解决：** 先把文档保存到磁盘；保存之前没有路径可复制。

## 不存在名为 "…" 的对齐模板.

- **原因：** 输入的名字，或快捷键里的 `template` 参数，不是 `textToolkit.alignByRegex.templates` 里的键。
- **解决：** 从输入框的列表里直接选模板，或检查设置里键名的拼写。

## 剪贴板没有可比较的文本内容. 图片等非文本内容无法比较.

- **原因：** VS Code 的剪贴板 API 只提供文本。只复制了图片时读到的是空串，与剪贴板为空无法区分。
- **解决：** 复制文本。同时复制图片和文字时，参与比较的是文字。

## 该命令需要恰好 2 个可见编辑器, 当前可见 … 个.

- **原因：** `比较两个可见编辑器` 要求屏幕上恰好有两个编辑器。
- **解决：** 拆分编辑器让两个文件同时可见，或改用 `比较两个已打开的标签页`，它不要求标签页可见。

## 归一化规则没有生效

- **原因：** 规则的 `match` 不是合法正则，缺少 `match` 或 `replaceWith`，或规则因 `"enableOnStart": false` 处于关闭状态。
- **解决：** 无效的规则会被跳过，并在开发者工具控制台（`帮助 > 切换开发人员工具`）里记一条 `[Text Toolkit] compare: skipped …`。改正规则，或用 `切换归一化规则` 打开它。diff 标题里的 `~` 表示比较打开时有规则生效。

## 大文件提示不再出现

- **原因：** 之前选了 `不再询问`，或 `textToolkit.plainText.promptSizeMB` 为 `0`。
- **解决：** 打开 `文本工具箱: 显示全部命令` → 纯文本模式 → `重新启用大文件提示`，并把 `promptSizeMB` 设为大于 `0` 的值。

## 纯文本模式下大文件仍然很慢

- **原因：** 这个模式省掉的是渲染和语言服务的开销，VS Code 仍会把整个文件读进内存。几百 MB 的文件依旧会慢，`files.maxMemoryForLargeFilesMB` 也仍然限制 VS Code 能打开的大小。
- **解决：** 这种体量的文件改用 VS Code 之外的分页查看器或日志查看器。见[无法加速的部分](plain-text-mode.md#无法加速的部分)。

## 比较副本变成了已删除文件的编辑器

- **原因：** 执行 `清理比较副本文件` 时，副本的标签页还开着。
- **解决：** 关掉这些标签页。下次清理前先关掉副本标签页；扩展不会自动删除任何文件。

## 按住 Cmd 或 Ctrl 指向终端选区时不出现链接

- **原因：** 选中之后鼠标还没移到过别的行，这一行超过 2000 个字符，选区从某个单词中间开始或结束，选区链接没有开启（`terminalOpen.selectionLink` 默认为 `false`），或者当前 VS Code 版本不允许扩展读取终端选区。
- **解决：** 把鼠标移到别的行再移回来，或改用终端右键菜单里的 `将终端选中文本作为路径打开` 或快捷键。见[已知限制](open-terminal-selection.md#已知限制)。

## 请先在终端中选中文本.

- **原因：** `将终端选中文本作为路径打开` 没有读到选中的文本。在 Claude Code 全屏模式这类接管鼠标的程序里，拖动只在程序内部高亮，终端本身没有选区。刚选完就执行时，VS Code 可能还没把选区传给扩展。扩展借助剪贴板读取选区时，VS Code 会自己提示终端没有可复制的选区。
- **解决：** 选中路径后再执行一次。在全屏程序里，按住 Option（Windows 和 Linux 上按住 Shift）拖动，或点提示里的 `打开剪贴板中的路径`，见[在 Claude Code 等全屏程序里选中](open-terminal-selection.md#在-claude-code-等全屏程序里选中)。

## 选中文本过长, 不可能是路径.

- **原因：** 选中的文本超过 4096 个字符，任何单条路径都不会这么长。
- **解决：** 只选中路径，或只选中包含路径的那几行。

## 无法读取终端选区: …

- **原因：** 当前 VS Code 版本不允许扩展直接读取终端选区，扩展改为借助剪贴板复制选区，而这次复制失败了，或超过 2 秒没有完成（`超时`）。冒号后面是具体原因。
- **解决：** 点一下终端让它成为活动终端，重新选中路径后再试。

## 剪贴板恢复失败.

- **原因：** 借助剪贴板复制选区之后，扩展没能把原来的剪贴板文本放回去。
- **解决：** 剪贴板里现在是选中的文本或一段临时标记；需要的内容请重新复制。

## 不存在: …

- **原因：** 显示的路径上没有文件或目录，常见原因是相对路径的起点不是你以为的那个目录。输入框下方的提示写明了这个目录及其来源；在 shell 里运行的程序（例如执行过 `:cd` 的 vim、tmux 或 `ssh`）不会改变它。回车后路径恰好消失时，输入框会再次弹出并提示 `仍不存在: …`。
- **解决：** 修改文本，直到提示变为 `将打开文件: …` 或 `将打开目录: …`；也可以输入绝对路径或 `~` 路径。保持 shell 集成开启，当前目录才会跟着 `cd` 变化，见[相对路径从哪个目录算起](open-terminal-selection.md#相对路径从哪个目录算起)。

## 无法确定终端工作目录, 请输入绝对路径

- **原因：** 没有任何来源给出终端的当前目录：没有 shell 集成，读不到 shell 的目录（Windows 上或终端退出后总是如此），终端启动时没有指定目录，也没有打开工作区文件夹。这时输入框下方的提示是 `无法确定终端工作目录, 只能输入绝对路径, ~ 路径或 file:// URI`。
- **解决：** 输入绝对路径、`~` 路径或 `file://` URI；或在 VS Code 里打开一个文件夹，让相对路径有起点。

## 无法从输入中解析出路径

- **原因：** 去掉引号、括号和标点后，剩下的文本不像路径；或者这是 `https://…` 这类网页链接，本命令把它留给 VS Code 处理。提示 `请输入路径` 表示输入框是空的。
- **解决：** 输入一条路径；`:行` 或 `:行:列` 后缀可写可不写。

## 无法访问 …: …

- **原因：** 路径存在但读不了：没有权限，或者文件系统 1.5 秒内没有响应（`超时`），较慢的网络盘上会出现这种情况。在输入框里输入时，同样的情况显示为 `无法确认是否存在: …`，仍然可以回车。VS Code 定位目录失败时也会出现这条提示。
- **解决：** 检查该路径及其上级目录的权限，或等网络盘恢复响应后再试。

## 无法打开 ….

- **原因：** 路径找到了，但 VS Code 没能打开它，例如文件在这期间被删除或替换。
- **解决：** 从资源管理器或用 `转到文件...` 打开这个文件，查看 VS Code 自己给出的错误。

## 无法打开终端选中的路径: …

- **原因：** 命令执行时遇到了意料之外的错误；冒号后面是错误信息。
- **解决：** 再试一次。如果反复出现，请带上这条提示和你选中的文本[提交 issue](https://github.com/HeavenSky/editor-text-toolkit/issues)。
