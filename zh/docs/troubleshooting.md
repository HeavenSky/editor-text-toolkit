# 故障排查

[English](../../docs/troubleshooting.md) · **简体中文**

按看到的提示或现象查找，每条给出原因和解决办法。提示文字引自中文界面。

## 当前文档尚未保存为文件.

- **原因：** 在未命名文档，或输出面板、虚拟文档这类没有对应文件的文档上执行了 `复制路径与行号`。
- **解决：** 先把文档保存到磁盘；保存之前没有路径可复制。

## 不存在名为 "…" 的对齐模板.

- **原因：** 输入的名字，或快捷键里的 `template` 参数，不是 `textToolkit.alignByRegex.templates` 里的键。
- **解决：** 从输入框的列表里直接选模板，或检查设置里键名的拼写。

## 剪贴板没有可比较的文本内容. 图片等非文本内容无法比较.

- **原因：** VS Code 的剪贴板 API 只提供文本。只复制了图片时读到的是空串，与剪贴板为空无法区分。
- **解决：** 复制文本。同时复制图片和文字时，参与比较的是文字。

## 该命令需要恰好 2 个可见编辑器, 当前可见 … 个.

- **原因：** `比较两个可见编辑器` 要求屏幕上恰好有两个编辑器。
- **解决：** 拆分编辑器让两个文件同时可见，或改用 `比较两个已打开的标签页`，它不要求标签页可见。

## 归一化规则没有生效

- **原因：** 规则的 `match` 不是合法正则，缺少 `match` 或 `replaceWith`，或规则因 `"enableOnStart": false` 处于关闭状态。
- **解决：** 无效的规则会被跳过，并在开发者工具控制台（`帮助 > 切换开发人员工具`）里记一条 `[Text Toolkit] compare: skipped …`。改正规则，或用 `切换归一化规则` 打开它。diff 标题里的 `~` 表示比较打开时有规则生效。

## 大文件提示不再出现

- **原因：** 之前选了 `不再询问`，或 `textToolkit.plainText.promptSizeMB` 为 `0`。
- **解决：** 打开 `文本工具箱: 显示全部命令` → 纯文本模式 → `重新启用大文件提示`，并把 `promptSizeMB` 设为大于 `0` 的值。

## 纯文本模式下大文件仍然很慢

- **原因：** 这个模式省掉的是渲染和语言服务的开销，VS Code 仍会把整个文件读进内存。几百 MB 的文件依旧会慢，`files.maxMemoryForLargeFilesMB` 也仍然限制 VS Code 能打开的大小。
- **解决：** 这种体量的文件改用 VS Code 之外的分页查看器或日志查看器。见[无法加速的部分](plain-text-mode.md#无法加速的部分)。

## 比较副本变成了已删除文件的编辑器

- **原因：** 执行 `清理比较副本文件` 时，副本的标签页还开着。
- **解决：** 关掉这些标签页。下次清理前先关掉副本标签页；扩展不会自动删除任何文件。
